# Focused P2 follow-up — storage validation and backup resource boundary

The first correction resolves the main lost-code, metadata, network deadline, cooldown, merge-navigation and product-copy findings; 192 tests and two real provider successes are reported. Astra inspected the changed implementations and local plugin attachment behavior. One focused second correction is justified by a new storage-trust bypass and incomplete resource-bound handling. This is the high-assurance exception for the image/storage architecture, not another general redesign pass.

1. `MediaAsset.verified(...)` is PUBLIC and accepts arbitrary id/MIME/bytes/dimensions while setting contentVerified=true. Any hand-built object can now bypass the repository's full check, directly contradicting the comment and REVIEW-P2 group4. Remove this unverified public path. Preferred small design: keep the normal public raw constructor untrusted; offer a validating public factory taking raw bytes, deriving SHA/MIME/dimensions itself; only a private constructor may set the verified marker. Move shared validation into that closed boundary so SnapshotCodec can use it in its isolate and compare claimed imported digest/MIME to the derived facts. Persisted DB rows may use the raw constructor (browsing need not validate them again; existing DB assets are already skipped on writes). No publicly supplied boolean, forgeable token, subclass override, or 'trusted caller' assertion. Make the class final if the marker can otherwise be overridden. Add a regression proving forged raw assets still fail repository writes atomically; inspect all public construction paths.

2. `BackupService.export()` still calls SnapshotCodec.encode synchronously on the UI isolate. `_estimateEncodedBytes` is neither an exact cap nor a conservative bound: it multiplies ASCII metadata by4 (rejecting files well below100MiB), ignores nested source fields, and underestimates control-character escaping (6bytes). Implement a bounded encoding path that aborts on the actual UTF8 output cap before accumulating arbitrarily oversized JSON; stream/count chunks or measure escaped output exactly before allocating the final buffer. Do not reject valid under-limit snapshots based on a rough estimate. Offload encoding to an isolate. Test both an under-cap ASCII/Unicode payload that the estimate would reject and over-cap escaped/nested-source metadata; picker must not open on failure. Preserve item/image caps.

3. While wiring the isolates, capture only sendable snapshot/text/limits locals or use a top-level task entrypoint. Current `_decode` references the `limits` instance field inside Isolate.run, which can capture the entire BackupService with repository and native picker. Add a regression using the DEFAULT isolate-enabled BackupService with a real SQLite repository and export/import roundtrip, not only decodeInIsolate:false fakes. This verifies the real mobile path is not dependent on accidentally sendable test dependencies. Expensive validation remains off UI without trusting public objects.

Keep changes limited to these storage/backup boundaries, supporting tests and report/evidence/README accuracy. No more provider calls or emulator attempts are needed. Run affected tests then one final full-suite/analyzer/format/APK pass, update final APK hash and REPORT-P2. Do not re-render unchanged UI or repeat previous unrelated tests individually. Root will review only these changes and final evidence. Reserve FINAL for the complete handoff; same worker and scope ownership.
