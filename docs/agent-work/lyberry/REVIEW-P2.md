# P2 consolidated review — corrections required

Astra reviewed the actual added/modified domain, SQLite, transport, provider, scan/editor/candidate/backup/settings code against the accepted P1 baseline, platform configuration, test/build logs, and three rendered screens. The style and broad functionality are aligned with the chosen design. 159 passing tests and Android debug compilation are supported by evidence. These concrete gaps prevent acceptance; fix them together in one correction bundle, preserving unrelated work.

## 1. Preserve identifiers and accurate provider metadata
`ItemDraft.fromCandidate` sets barcode to empty and `ScanScreen._handleIdentifier` does not restore the scanned/typed code. Every successful scan-to-match save therefore loses the code. Pass the normalized identifier into the chosen draft and assert it persists through save. Make ISBN10/13 and UPC/EAN equivalent forms work at provider matching/routing/cache boundaries, not merely in an unused `equivalents` property. MusicBrainz currently checks only `barcode == code`; UPC labels all results possible even when identifiers exactly match.

Open Library `_editionCreator` turns `/authors/OL...A` into a displayed author id. Do not present IDs as names: resolve the author with a rate-limited request or enrich the edition with matching search author names, otherwise leave empty. A later search failure must not discard a successful edition candidate. Use real supplied UPC description rather than substituting only its category, and keep malformed provider shapes distinct from a genuine empty list. Current adapters silently turn e.g. `[]`, `{}` or wrong-shaped releases/items/docs into no match.

## 2. Routing, quotas and bounded lookup completion
`MetadataService.lookup` calls every supporting provider concurrently when hint is null, including Open Library for music UPCs and UPCitemdb for successful book matches. Apply the agreed route: ISBN => books first; other codes => music when appropriate; general UPC fallback only when needed (or directly for DVD/Blu-ray/games hints). Preserve usable partial candidates and warnings. Do not cache a partial result as fully successful for 12 hours while discarding its failures; retry must have a way to requery the failed provider after cooldown.

`ProviderRateLimiter.acquire` waits through arbitrary cooldowns and `Future.wait` holds all results until it completes. After any failure the service also imposes a default 60s penalty. This causes long spinners even when other candidates are ready and hides manual entry. Return an immediate typed cooldown result instead of waiting/retrying after a quota response; apply spacing independently and expose its state without hiding manual add. Put the throttle at actual HTTP-request boundaries: Open Library does edition + search back-to-back under only one current acquire, violating its per-request rate.

UPC `_resetDelay` treats X-RateLimit-Reset as a duration, but it is a Unix epoch timestamp. This can impose a multi-decade wait. Verified primary source: https://www.upcitemdb.com/wp/docs/main/development/api-rate-limits/ (HTTP headers section). Subtract the injected current UTC time, clamp stale reset to zero. `parseRetryAfter` uses DateTime.tryParse and cannot parse standard HTTP dates; use HTTP-date parsing and an injected clock. Add tests with a real-sized epoch, RFC HTTP date, concurrent requests, partial result plus cooling provider, and retry after a transient failure. No automatic deferred requests after a user abandons the lookup.

## 3. Scanner has competing lifecycle owners and an unguarded manual path
`MobileScannerController` uses default autoStart, the widget uses `useAppLifecycleState:true`, and ScanScreen separately starts/stops it. `_cameraActive` can disagree with actual plugin state. App resume unconditionally starts the scanner even while candidates/editor cover its route (including gallery/camera handoffs). Manual submission bypasses ScanCoordinator's handling guard and can push duplicate lookups on rapid taps. Use one camera lifecycle owner with explicit autoStart policy, actual controller state or a serialized injectable camera seam, and route/app visibility gates. Funnel manual and detected codes through one in-flight guard. Camera must stay stopped throughout candidate/editor/picker flows and after disposal; resume only on visible scanner return. Add lifecycle/rapid-manual/route-hidden tests (the current five coordinator tests do not test these conditions). Manual add must remain immediately available during slow/offline lookup; remove the misleading claim that online lookup works offline.

## 4. Enforce export size and avoid repeating expensive work on UI isolate
`SnapshotCodec.encode` checks image/item limits but never checks the UTF8 encoded file against maxFileBytes. Valid long metadata can export a file the same app refuses to import. Use a bounded encoding path that stops at the cap before handing bytes to native save, including multibyte metadata. `BackupExportResult.byteLength` is string.length, not byte count. Export should fail before the picker on over-limit content; test with small injected limits and Unicode. Keep the UI responsive during large encode and import apply: decoding is off-isolate but repository `_assertAssetMatchesBytes` decodes every new imported raster again on the UI isolate. Retain write-boundary validation, moving expensive image work off-isolate or using a safe validated handoff without accepting forged public objects.

## 5. Back during an applying merge reports a false cancellation
MergePreview disables its Cancel button but allows app-bar/system back while the transaction is running. Settings then reports `Import cancelled. Nothing changed.` even though the database can commit. Guard navigation while apply is in flight or propagate an accurate detached operation outcome; before confirmation cancel must still have zero changes. Add a delayed merge test for back and double-confirm, including the reported result and refreshed library. Do not allow a completed async action to pop some other route.

## 6. Bound the full HTTP operation and contain cover failures
`IoHttpTransport` times out headers and then uses stream.timeout (an inactivity timer), so a slow trickle can keep the operation alive indefinitely. Enforce an overall deadline and cancel/abort underlying work on deadline or size overflow; normalize streamed network errors into TransportException as well as initial send errors. Use a local injected client/stream test for trickling and mid-stream failure; do not hit live services for these tests. CoverDownloader currently only catches TransportException around get, so an unexpected stream error or invalid redirect can escape into an unawaited editor fetch. Cover failures must always become a placeholder. Keep the conservative HTTPS redirect/host/byte policy. Avoid broadening allowed subdomains beyond archive.org unless needed and justified.

## 7. Prevent stale cover responses from replacing user choices
Editor `_fetchCover` can finish after the user removes/replaces the cover or selects a newer candidate and then overwrite that choice. Add a request/choice generation guard invalidated by manual cover changes/removal/new lookup, and by save/disposal. Slow download must not replace a newer local photo or different candidate. Test delayed responses in reverse order and manual override; saving with a failed/unready cover must remain possible.
